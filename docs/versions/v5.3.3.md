# V5.3.3 更新说明

> 发布日期：2026-11-16

Bug 修复版本，集中在验证码提取准确性与「邮箱被删除后界面残留」两处体验问题。
无 DB 变更，无配置变更，拉代码后 `wrangler deploy` 即可。

## 主要变更

### 1. 验证码不再误判为邮箱地址 / 链接里的数字（[#75](https://github.com/idinging/freemail/pull/75)）

此前只要正文出现一个孤立的 6 位数字就会被当作验证码展示。典型场景是一封转发邮件，
发件人是 `xxx888888@example.com`，页面顶部直接显示「验证码 888888」。

验证码有两条提取链路，本次两条都修：

| 链路 | 位置 | 改动 |
|---|---|---|
| 后端（写入消息的 `verification_code`） | `src/email/parser.js` | 匹配前剔除 HTML、URL 与邮箱地址；新增日期判定 |
| 前端（详情/列表的兜底展示） | `public/js/modules/app/ui-helpers.js` | 匹配前剔除 HTML 标签、邮箱地址与 URL；兜底规则边界收紧 |

后端这一条必须一并修：前端调用处是 `e.verification_code || extractCode(...)`，库里已有值时就
不再走前端兜底，只改前端不会生效。

顺带修掉「转发邮件头部被当成验证码」的同类问题——转发邮件必然含 `Date: 2026-10-29` 这样的头部，
归一化后是 `20261029`，与 `login` / `security` / `code` 等关键词同处一个窗口时会被误取，
现已按日期特征排除。

### 2. 支持分组写法的验证码

早期版本只认连写和「单数字 + 分隔符」，`458-291`、`12 34 56`、`123 456` 这类分组写法一直取不到，
现已支持；同时保留 `8 8 2 9 1 3` 这类逐位写法，不会因分段数被截断而返回残缺验证码。

### 3. 邮箱被管理员删除后，访客端不再停留在已删地址（[#76](https://github.com/idinging/freemail/pull/76)）

普通用户正在查看的邮箱被管理员删除后，前端会一直显示该地址（刷新也一样），邮件列表只是变成
「暂无邮件」——因为 `GET /api/emails` 对不存在的邮箱返回 `[]`，和「邮箱存在但没有邮件」完全同形。

修复后：

- `GET /api/emails` 在邮箱不存在时仍返回 `[]`（响应结构不变），额外带 `X-Mailbox-Missing: 1`
- 前端读到该响应头后清空当前邮箱、停止轮询、恢复占位状态并提示「该邮箱已被管理员删除，请重新生成」
- 选中邮箱前先校验存在性，刷新页面也不会「复活」已删地址

响应结构未变、只加了一个响应头，因此前后端可以分开部署，任一方向先上线都不会出问题。

### 4. 新增验证码提取测试

`src/test/test_code_extraction.js`，25 个用例覆盖前后端两条链路：邮箱/URL 误报、逐位与分组写法、
日期、HTML 包裹、中英文关键词。运行：

```bash
node src/test/test_code_extraction.js
```

## 兼容性

- 无 DB schema 变更，无需迁移
- 无新增/变更环境变量
- 升级方式：拉代码 → `wrangler deploy`
- 已存的历史消息仍保留旧的 `verification_code` 值，本次只影响新收邮件；
  如需刷新旧数据，可按需重新解析对应 EML

## 已知限制

- 前端兜底的「关键词 + 4-8 位数字」规则仍可能对极个别营销邮件给出可疑结果，属启发式上限
- 邮箱被删除的场景只覆盖收件箱视图，「发件箱」标签页未改动
